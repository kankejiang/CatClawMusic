## 六、技术债与风险

1. **播放链路**：在线曲目前存 `outer/url`（稳定、可缓存、128k）。要做无损，必须「播放前取链」——两条路：给 `PlayerController` 加 `urlResolver` 钩子（改动核心），或在 `NeteasePlayback` 构造队列时对当前曲取链（已实现，仅当前曲）。建议 P0 抽 `NeteasePlayUrlResolver`，统一管理缓存与降档，播放器只在起播前调一次。
2. **歌词**：`NeteaseApiClient.lyrics` 已能取三流，但播放页的歌词管线只认本地/内置歌词；需要按 `remoteId` 增加在线歌词源并落盘缓存。
3. **会话**：`NeteaseWeapi` 已能读 `Set-Cookie`；续期要新增 `/eapi/login/token/refresh` 并把新 cookie 写回 `NeteaseSession`，登录时启动 6 小时定时。
4. **缓存**：直链 20 分钟建议与插件一致（`Map<songId:quality, url+expire>`）；封面已统一 `?param=NxN`。
5. **测试**：当前只有链接解析 / 匹配 / 客户端解析单测；P0 起补歌词解析、音质降档、打卡上报的纯逻辑测试。
6. **增量编译坑**：本轮多次出现 `assembleDebug` 未把改动打进 dex，UI 不生效时先 `:app:clean :app:assembleDebug`。

## 七、建议立即开工顺序

1. 在线歌词接入（用户感知最强）
2. 音质档位 + 直链缓存（listen 体验）
3. 私人漫游续播 + 听歌打卡（推荐闭环）
4. 会话续期（避免“过几天又要登录”）
5. 搜索歌手结果 + 分页（当前最明显的功能缺角）

后续按 P1 的页面顺序补：歌单广场 → 榜单块 → 歌手页 → 专辑页 → 评论。
